# Migration 141 — platform_activation_requests

Source: `platform_activation_requests` in `postgres_effective_schema_snapshot.json`.

## Porting decisions

- Preserves all nine source columns and their nullability/default semantics.
- Uses `BIGINT GENERATED BY DEFAULT AS IDENTITY` for the SQLite AUTOINCREMENT row identifier.
- Keeps `school_id` as PostgreSQL `INTEGER` so it matches `schools.id` in the PostgreSQL baseline.
- Preserves the source foreign key to `schools(id)` with default NO ACTION behaviour.
- Keeps status, timestamps, approver metadata and activation-code delivery metadata as TEXT for application compatibility.
- Recreates the source index on `(status, submitted_at)`.
- Does not invent CHECK constraints, unique constraints, or triggers absent from the source schema.

## Validation

The migration validates exact column names/types/nullability, the primary and school foreign-key constraints, the status index definition, and absence of triggers. Automated tests use a catalog-response fake. A live PostgreSQL server was not available for execution in this stage.

## Isolation

Migration 141 is registered in the standalone PostgreSQL migration registry only. It is not imported by SQLite startup and does not modify the existing SQLite or browser IndexedDB offline-sync implementation.

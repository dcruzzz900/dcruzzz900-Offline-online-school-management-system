# Stage 35 — PostgreSQL migration 108: `announcement_dismissals`

## Source review

Reviewed the effective SQLite schema snapshot and confirmed:
- Five columns: `id`, `announcement_id`, `actor_type`, `actor_id`, `dismissed_at`.
- No declared foreign keys.
- No standalone secondary indexes; SQLite reports one auto-index generated by the UNIQUE constraint.
- No table-specific triggers.
- Composite uniqueness on `(announcement_id, actor_type, actor_id)`.

## Implementation

- Added `postgres_migration_108_announcement_dismissals.py`.
- Used a BIGINT identity primary key and BIGINT identifier columns.
- Preserved `dismissed_at` as TEXT with `CURRENT_TIMESTAMP` default.
- Preserved composite uniqueness as a named PostgreSQL UNIQUE constraint.
- Added schema, foreign-key, and uniqueness-index validation.
- Registered migration 108 in the standalone PostgreSQL registry.
- Updated previous registry expectations and added focused migration contract tests.

## Scope and limitations

This is an additive, standalone PostgreSQL migration. It is not connected to
Flask/SQLite startup and does not change SQLite or browser IndexedDB behaviour.
It does not migrate data. Unit/contract tests do not prove execution against a
live PostgreSQL server; live DDL and duplicate-row behaviour must be tested
before production use.
